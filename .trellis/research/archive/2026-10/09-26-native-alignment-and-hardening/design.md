## 2. 核心决策 D1：折叠行为交还 ST 原生处理器

### 问题

`SettingsDrawer` 自建了一套折叠逻辑，与 ST 原生处理器在同一事件上互斗（子任务 1 的 `design.md` 载有完整证据链）。这是「折叠不上」的直接成因。

### 决策

**删除扩展自建的折叠逻辑，把折叠行为完全交还 ST 原生委托处理器。** 理由：

1. ST 的原生处理器是 **document 级委托**（`$(document).on('click', '.inline-drawer-toggle', …)`），动态插入的面板天然被覆盖——扩展不需要、也不应该自己再实现一遍。
2. 保留自建实现意味着**永久维护与宿主行为的同步**，且每次宿主调整动画/图标类名就会再次错位。
3. 交还原生处理器的副作用是正面的：与页面内其它扩展的抽屉行为**完全一致**（这正是用户的「原生风格」诉求）。

### 代价与规避

ST 的 `slideToggle()` 通过切换 `display` 实现动画，因此**内容容器不能依赖 `display:flex` 表达布局**。规避方式为「双层结构」——外层 `.inline-drawer-content` 交给宿主控制 display，内层新增一个纯布局容器承载 flex/gap。详见子任务 1 `design.md`。

## 3. 核心决策 D2：原生接管的接缝选择（禁止 monkey-patch）

### 决策

接管 ST 原生背景选择器**只允许使用以下接缝**，按优先级排序：

| 优先级 | 接缝 | 性质 | 用途 |
| --- | --- | --- | --- |
| P0 | `eventSource.emit(event_types.FORCE_SET_BACKGROUND, …)` | **公开事件** | 驱动宿主走它自己的背景应用路径 |
| P0 | 捕获阶段原生监听 `document` 上的 `.bg_example` click | **DOM 标准能力** | 拦截原生选择（ST 的处理器是冒泡阶段委托，捕获阶段先执行） |
| P1 | `/api/backgrounds/upload\|all\|delete` | **公开 HTTP 接口**（已在用） | 与原生共用同一存储目录 |
| P2 | `#bg1` 的 `background-image` 内联样式 | **DOM 可读** | 读取当前原生背景态 |
| ✗ 禁止 | `setBackground()` / `background_settings` | **模块私有，未导出、未挂 window** | 不可用；不得尝试 hack |

### 兼容性契约

- 接管必须**可降级**：当上述接缝任一不可用（宿主版本变化、DOM 结构变化）时，扩展回退为当前的「仅增强」模式（徽章标注 + 点击接管自身管线），媒体功能**完全不受影响**。
- 接管必须**可退出**：用户显式点选原生图片背景时，视为退出接管、还原原生行为。
- 所有接缝探测集中在单一模块内，宿主升级时只需改一处。

### 已知副作用

`FORCE_SET_BACKGROUND` 会把背景写入 chat 元数据（聊天气泡背景），属宿主既有语义。使用时须评估是否可接受；若不可接受，改用「扩展自行渲染 + 回写原生选中态」的路线。

## 4. 核心决策 D3：视觉规范的单一真源

「原生风格」不能靠逐条改样式达成，否则必然漂移。决策：

1. **颜色/圆角/边框/字号一律取 ST 主题变量**（`--SmartThemeBodyColor`、`--SmartThemeBorderColor`、`--SmartThemeQuoteColor`、`--SmartThemeBlurTintColor`、`--SmartThemeEmColor`），保留 `var(--x, fallback)` 形式以兼容变量缺失。
2. **选中态不用发光表达**，改为「边框加粗 + 前景对比度」。这是与原生缩略图选中态一致的表达方式，也直接满足「不做溢光按钮特效」。
3. **例外白名单**：仅两处允许保留固定色值与投影，且必须在 CSS 注释中写明豁免理由——
   - 媒体类型语义徽章的五色（须跨主题可读，跟随主题反而会读不出）；
   - 浮动迷你播放器胶囊的层级投影（表达 `position:fixed` 悬浮关系，非发光特效）。
4. 该规范落盘到 `.trellis/spec/frontend/`（子任务 1 执行），使后续改动有据可依。

## 5. 健壮性分级的判定标准（子任务 2 使用）

| 级别 | 判定 | 处置 |
| --- | --- | --- |
| P0 | 数据丢失 / 用户可见功能失效 / 未捕获异常中断主流程 | **必做** |
| P1 | 竞态、资源泄漏、无界增长、跨设备状态错乱 | **必做** |
| P2 | 性能热点（进主路径）、边界未校验（外部输入）、错误静默 | **做**（不改契约） |
| P3 | 可读性、重复代码、死代码 | **列入清单，用户拍板** |
| P4 | 纯外观、无行为影响 | **不做**，除非与其它项同一文件顺手 |

「未获批准不动手」的硬约束：子任务 2 的 `implement.md` 中，**删除类条目不得出现在勾选清单里**，只允许出现在独立的「候选清单」文档中。

## 6. 兼容性与回滚

- 无服务端改动、无数据迁移、无实例部署。
- 所有改动为前端源码 + `dist/` 重建产物，按子任务粒度提交。
- 每个子任务自带回滚点（见各自 `implement.md`）。
- 父任务最终复核若发现跨子任务集成问题（如子任务 3 的样式与子任务 1 的规范冲突），由父任务裁决并回退到对应子任务修正。
